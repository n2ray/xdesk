# XDesk 0.6.2

[中文说明见下方](#xdesk-062-1)

Fixes from an audit of the display paths: the screen, the wireless and browser displays, and the Mac's picture. It installs over 0.6.1.

## Fixed
- **Browser display:** a page that sent its first message a byte at a time could hold a connection, and the one pairing attempt, past its time limit, keeping others from pairing. Every read now ends at the limit.
- **Mac picture:** when the video decoder failed while finishing a picture, the whole Mac connection dropped and came back, instead of going on with the next decoder.
- **Mac picture:** one frame larger than the decoder's buffer (a big Retina keyframe) switched the Mac to the slow software decoder for the rest of the connection. The decoder now starts again with room for it; a broken frame is dropped and a keyframe asked for.
- **Linux desktop:** a cursor 512 pixels or larger made the renderer read past the cursor's memory; the default cursor now shows, at its own size.
- **Linux desktop:** the X server checks the length of clipboard text it receives, and reads all of it.
- **Linux desktop:** the port the app knocks on to find the X server (7892) now listens on this device only, not the network, and checks the whole knock.
- **Screen:** if the GPU could not start the renderer, the app could freeze (and Android offer to close it); closing the screen right after opening it could crash. Neither waits on the renderer any more.
- **Screen:** a log line written for every copied rectangle of every frame now only with debugging on.
- **Mac app:** a message longer than 16 MB ended the connection cleanly instead of garbling the messages after it.
- **Mac app and web display:** in the Launchpad and the Dock the pointer lagged behind the mouse: it was XDesk's arrow drawn into the picture. There, as over apps, the computer's own pointer now shows.

## Changed
- **One name, one bar:** the Dock's All, and Overview on XDesk Receiver, the web display and the Mac app, are now all called **Launchpad**, as they open the same thing. The web display and the Mac app open their buttons from a blue handle on the right edge, as XDesk Receiver does, instead of a bar at the top.
- **The keys button** (键鼠在外屏 / 键鼠在本机) is only there with a keyboard or mouse on the phone, which is all it switches. It is called Input now; its icon says where they are: blue, with the mouse joined to the screen, on the display.

## Upgrading
- Install the APK over 0.6.1. XDesk Receiver has only the new name; the `xdesk` command is unchanged apart from the version number.

# XDesk 0.6.2

显示链路审计后的修复版，覆盖外屏、无线和浏览器投屏、Mac 画面。覆盖安装在 0.6.1 上即可。

## 修复
- **网页投屏**：网页把第一条消息一个字节一个字节地慢慢发，就能让连接（以及唯一的一次配对机会）超过时限一直占着，别人无法配对。现在每次读取都受时限约束。
- **Mac 画面**：视频解码器在输出画面时出错，会让整个 Mac 连接断开重连，而不是换下一个解码器接着放。
- **Mac 画面**：一帧大过解码器的缓冲区（Retina 的大关键帧），这条连接之后就一直用慢的软件解码。现在会给解码器更大的空间重新开始；坏帧丢掉，再要一个关键帧。
- **Linux 桌面**：512 像素或更大的光标会让渲染器读出光标内存的范围；现在改为显示默认光标，并用它自己的尺寸。
- **Linux 桌面**：X 服务器收到剪贴板文字时检查长度，并完整读完。
- **Linux 桌面**：App 用来找 X 服务器的敲门端口（7892）现在只听本机，不再对网络开放，并完整核对敲门内容。
- **外屏**：GPU 无法启动渲染器时，App 可能卡住（Android 提示是否关闭）；刚打开外屏马上关掉，可能崩溃。现在两者都不会再等渲染器。
- **外屏**：每帧每个复制矩形都写一条日志，现在只在调试时写。
- **Mac 版**：收到超过 16 MB 的消息时干净地断开连接，而不是把后面的消息全部读错位。
- **Mac 版和网页投屏**：在启动台和 Dock 上指针跟不上鼠标，因为那是 XDesk 画进画面里的箭头。现在这两处和应用上一样，显示电脑自己的指针。

## 改动
- **统一名称和操作**：Dock 的「全部」，以及 XDesk Receiver、网页投屏、Mac 版里的「总览」，打开的是同一个东西，现在都叫**启动台**。网页投屏和 Mac 版的按钮改成和 XDesk Receiver 一样，从右边的蓝色把手打开，不再是顶部的工具栏。
- **键鼠按钮**（原来的「键鼠在外屏 / 键鼠在本机」）只在手机接了键盘或鼠标时才出现，它本来也只管这些设备。按钮名改成「键鼠」，在哪边看图标：蓝色、鼠标和屏幕连着线，就是在外屏。

## 升级
- APK 覆盖安装在 0.6.1 上。XDesk Receiver 只改了名称；`xdesk` 命令除了版本号没有变化。
