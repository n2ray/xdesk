# XDesk 0.6.0 beta 1

## What this beta is

v0.6.0-beta.1 is a pre-release of the 0.6.0 rewrite: one switchboard for everything, devices added on demand, Linux programs as apps, Mac support through Sill, and the X side's own input method. It installs over 0.5.1, which stays the stable version. This is a beta: the new parts have been tested less than the rest, and some known limits are listed below.

## Highlights

### Switchboard and Dock

- One switchboard, three faces: the list on the phone, the Launchpad grid that is the external display's home, and the docks. One model, shared tabs (running, favourites, phone, every device) and shared search, across all devices, pinyin initials included.
- A dock at the bottom edge over any content: push the pointer against the edge to open it (Android apps, Linux and Mac alike), move away to close.
- One card for every item, wherever it is: long-press on the phone or right-click on the display. The item on the display has **Open the Launchpad**, which opens the Launchpad over it without ending it.
- A small badge on the icons of other devices' items (a display for a Mac, `>_` for Termux, a proot or chroot's initial), so favourites and the docks say whose item it is.
- Physical keyboard and mouse belong to the external screen by default; Ctrl+Alt+M moves them to the phone and back.
- XDesk's own screens are sized by the screen's **Size** setting; **Android apps' interface size** applies only to Android apps.

### Devices

- Devices added on demand. The first start shows the phone's own apps only. **Add device › Linux** adds Termux and the proot or chroot environments the `xdesk` command knows; **Add device › Mac** pairs a Mac. Windows and other Android devices say "coming later".
- Linux environments are local devices: no connect or disconnect, their apps are always listed, opening a program starts a light X on demand (no panel, no desktop), and **Stop** replaces Disconnect.
- **Whole desktop** is first in every Linux tab and the only thing that starts the desktop session.
- Without Termux, the add page says to install it first. With Termux but no `xdesk` in it yet, the Termux tab and the add page offer **Install xdesk in Termux**: it copies the install line and opens Termux.
- If Termux is removed or reinstalled, XDesk notices (a dialog says so) and forgets everything it knew of the old one: environments, sessions, devices, hidden items, Linux favourites and recents, the program list.

### Input

- A physical keyboard types through the input method of the content: fcitx5 in Termux for Linux, with its candidates on the external screen at the text; the Mac's own for a Mac; the phone's when neither runs.
- The X side's input method comes with `xdesk ime setup` (says what to install if fcitx5 is missing, then writes a first config and starts it); Shift+Space switches the input method.
- The X side's keyboard layout is remembered: `xdesk ime layout NAME` (e.g. `de-nodeadkeys`, `auto` to forget), also a row on the Linux device page. A fresh X server starts with `us`.
- Each Linux device and each Mac has a switch **Keyboard types with the phone's input method**.

### Mac

- A Mac is a device: pair by its address and the 12-digit code, by the QR code in Sill's pairing window, by a `sill://` link, or tap **Ask the Mac for a code**. Needs Sill 0.6.1 or later on the Mac.
- Mac windows, apps and the desktop as contents on the display; a locked Mac says so and the whole desktop unlocks it; **Fit to screen** resizes a window and Sill puts it back.
- Picture modes **Sharp / Balanced / Smooth** in one tap (Quick quality), Ctrl+Alt+Q cycles them while a Mac is on the display, and **Lower quality automatically on a weak link** steps down and back up by itself. The picture and sound page shows the round trip, with advice when it stays high.
- Sound: **Play the Mac's sound here (experimental)** is on by default and needs the Mac's own **Send Audio** in Sill. **Mute this device**, and pulling the wired or Bluetooth headphones the sound goes to mutes it until you unmute. The sound plays without lip sync.
- The XDesk Mac app (the Mac as the big screen) still works: USB or Wi-Fi, moving between them by itself, files and clipboard shared. A Mac receiver tells the phone it is a Mac keyboard, so Command stays Command.

### Receivers

- XDesk Receiver's handle has **Overview** (opens the switchboard on the display) and **Switcher** (one step of the app switcher) next to Back and Home.
- The web display's toolbar has Back, Home and **Overview**.
- The phone's touch settings (natural scrolling, pointer speed, scroll speed) are sent to receivers, so they feel like the phone.

### Linux and Termux

- Linux programs as apps: the launcher lists each environment's `.desktop` programs and opens them one by one; a program's window becomes the content and ends when its window closes.
- `xdesk` grows: `envs`, `apps`, `launch`, `ime` and `ime layout`, and `NAME+apps` sessions with only the window manager. The installer and `xdesk ime setup` can be run again over an existing setup.
- The installer now asks before it turns on `allow-external-apps` (it explains and waits for `y`), and on Adreno it installs Turnip; Mesa then runs OpenGL on the real GPU through zink and falls back to software rendering on GPUs too old for Turnip.

## Known limits

- The receiver paths (XDesk Receiver, the web display, the Mac app) were not retested on real devices in this round.
- proot and chroot environments are little tested.
- Mac sound plays without lip sync.
- One full screen content at a time. Split screen, several windows and multiple displays (phase 2), Windows support and receiver protocol v3 come later.
- As before: Android apps need activation (wireless debugging or Shizuku), and the beta is used daily on a single phone.

## Upgrading

- Install over 0.5.1; the APK has had XDesk's own release key since v0.2.0. The releases page keeps 0.5.1 as the latest stable.
- If the desktop was running while XDesk updated, the X server is still the old build; XDesk asks once to restart the desktop (its programs close). If it cannot ask, run `xdesk stop` then `xdesk start` in Termux.
- Existing users keep their Termux device: if the old app could run `xdesk`, Termux is added automatically on upgrade.
- Run the installer again in Termux (`curl … | bash`) to get the new `xdesk` command with `envs`, `apps`, `launch` and `ime`.
- Install the new `xdesk-receiver.apk` on receiving devices for the new handle buttons, and the matching `XDesk-macos-arm64.dmg` on a Mac.

# XDesk 0.6.0 beta 1

## 这个测试版是什么

v0.6.0-beta.1 是 0.6.0 重写版的预发布版本：一个交换台管所有内容，设备按需添加，Linux 程序当应用，通过 Sill 支持 Mac，还有 X 这边的输入法。可以直接装到 0.5.1 上，正式版仍是 0.5.1。这是测试版：新功能的测试比原有部分少，已知局限见下文。

## 亮点

### 交换台和 Dock

- 一个交换台、三种样子：手机上的列表、外接屏的首页（启动台）、以及 Dock。一份模型，标签（正在运行、收藏、手机、每个设备）和搜索两块屏共用，搜索覆盖所有设备，支持拼音首字母。
- 任何内容上都能打开底边的 Dock：把光标向屏幕底边推（安卓应用、Linux、Mac 都一样），移开收起。
- 任何条目都是一张卡片，在哪里打开都一样：手机上长按，或外接屏上右键。正在外接屏上的那一项，卡片里是**打开启动台**：在它上面盖出启动台，不结束它。
- 其他设备的条目图标带小徽章（Mac 是显示器、Termux 是 `>_`、proot / chroot 是发行名首字母），在收藏和 Dock 里一眼就能分清。
- 实体键盘和鼠标默认归外接屏，Ctrl+Alt+M 在手机和外屏之间切换。
- XDesk 自己的界面按屏幕的「**大小**」设置走；「**安卓应用界面大小**」只对安卓应用生效。

### 设备

- 设备按需添加。第一次打开只有手机自己的应用。「添加设备 › Linux」添加 Termux 和 `xdesk` 命令知道的 proot / chroot 环境；「添加设备 › Mac」配对 Mac。Windows 和其他安卓设备显示「即将支持」。
- Linux 环境是本地的设备：没有连接 / 断开，应用列表一直显示，点程序按需起轻量 X（没有面板和桌面），「停止」取代断开。
- 「**整个桌面**」排在每个 Linux 标签的最前面，也是唯一会启动桌面会话的东西。
- 没装 Termux 时，添加页会提示先安装 Termux；装了 Termux 但里面还没有 xdesk 时，Termux 标签和添加页里都有「**在 Termux 里安装 xdesk**」：复制安装命令并打开 Termux。
- Termux 被删除或重装后，XDesk 会弹窗告诉你，并忘掉关于旧 Termux 的一切：环境、会话、设备、隐藏项、Linux 的收藏和最近使用、程序列表。

### 输入

- 实体键盘打字走内容那一边的输入法：Linux 用 Termux 里的 fcitx5，候选框显示在外接屏上、紧挨着文字；Mac 用 Mac 自己的输入法；两边都没有时用手机的。
- X 这边的输入法：`xdesk ime setup` 在没装 fcitx5 时会提示要装哪些包，然后写第一份配置并启动它；Shift+空格切换输入法。
- X 这边的键盘布局会被记住：`xdesk ime layout 名字`（如 `de-nodeadkeys`，`auto` 取消），Linux 设备页上也有这一行。新起的 X 服务器默认是 `us`。
- 每个 Linux 设备和每台 Mac 都有「实体键盘用手机输入法打字」开关。

### Mac

- Mac 是一个设备：输地址和 12 位配对码、扫 Sill 配对窗口的二维码、点 `sill://` 链接，或点「**让 Mac 显示配对码**」。Mac 上要装 Sill 0.6.1 或更新版本。
- Mac 的窗口、应用和桌面都能放到外接屏上；Mac 锁着会有提示，打开整个桌面就能解锁；「**适配屏幕**」改窗口大小，串流结束后由 Sill 恢复。
- 「**快速画质**」一键切换 清晰 / 平衡 / 流畅，外接屏上是 Mac 时 Ctrl+Alt+Q 循环切换；「**网络变差时自动降低画质**」自动降档，链路恢复后再升回去。「画面和声音」页里有网络往返，一直偏高时给建议。
- 声音：「**在这里播放 Mac 的声音（实验）**」默认打开，需要 Mac 在 Sill 里打开自己的「Mac 发送声音」。「**静音这台设备**」，另外声音所走的耳机被拔掉时也会静音，关掉开关才恢复。声音没有口型同步。
- XDesk Mac 版（用 Mac 当大屏）照旧：USB 或 Wi-Fi 自动切换，文字和文件互传。Mac 接收器会告诉手机自己是 Mac 键盘，所以 Command 保持为 Command。

### 接收器

- XDesk 接收器的把手在返回、主页之外多了**总览**（在外接屏上打开交换台）和**切换器**（切一次应用）。
- 网页显示的工具条有返回、主页和**总览**。
- 手机的触控设置（自然滚动、光标速度、滚动速度）会下发给接收器，手感跟手机一样。

### Linux 和 Termux

- Linux 程序当应用：启动器列出每个环境的 `.desktop` 程序，逐个打开；程序的窗口成为内容，窗口关了内容就结束。
- `xdesk` 新增 `envs`、`apps`、`launch`、`ime` 和 `ime layout`，以及只有窗口管理器的 `NAME+apps` 会话。安装脚本和 `xdesk ime setup` 都可以在已有环境上重跑。
- 安装脚本现在会先询问再打开 `allow-external-apps`（说明后等 `y`）；Adreno 手机上装 Turnip，Mesa 通过 zink 用真实 GPU 跑 OpenGL，GPU 太老时自动退回软件渲染。

## 已知局限

- 接收端的几条路（XDesk 接收器、网页显示、Mac 版）这一轮没有在真机上重新测试。
- proot 和 chroot 环境测试得少。
- Mac 的声音没有口型同步。
- 同一时间只能放一个全屏内容。分屏、多窗口、多块屏（第二阶段）、Windows 支持和接收器协议 v3 都还没做。
- 和以前一样：安卓应用需要激活（无线调试或 Shizuku），测试版平时只在一台手机上用。

## 升级

- 直接装到 0.5.1 上，APK 从 v0.2.0 起就是 XDesk 自己的签名。发布页的正式版仍是 0.5.1。
- 如果更新时桌面还在跑，X 服务器还是旧版本，XDesk 会问一次是否重启桌面（里面的程序会关闭）。问不了的话，在 Termux 里运行 `xdesk stop` 再 `xdesk start`。
- 老用户的 Termux 设备会保留：旧版能用 `xdesk` 的话，升级后 Termux 自动算已添加。
- 在 Termux 里重跑一遍安装脚本（`curl … | bash`），拿到带 `envs`、`apps`、`launch`、`ime` 的新 `xdesk` 命令。
- 接收设备上装新的 `xdesk-receiver.apk` 才有新的把手按钮；Mac 上装对应版本的 `XDesk-macos-arm64.dmg`。
